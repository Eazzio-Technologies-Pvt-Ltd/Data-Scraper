# **1. Design Philosophy**

BizScraper Pro must look like a tool built by a senior frontend developer — not generated by AI. Every design decision below is intentional, restrained, and tied to the product's purpose: fast, clean business data extraction.

| **AI-Generated Look (avoid)** | **Human-Coded Look (target)** | **How We Achieve It** |
| --- | --- | --- |
| Neon gradients, glowing borders | Flat, muted, intentional colour | Single accent colour only — no gradients on UI elements |
| Inter/Roboto at max weight everywhere | Two distinct typefaces, mixed weights | DM Sans (body) + DM Mono (data/labels) |
| Div soup, symmetric blocks | Semantic HTML, intentional whitespace | Use <main>, <section>, <article> — asymmetric spacing |
| Animations on everything | One subtle micro-interaction only | Fade-in on results table only — nothing else moves |
| Purple/blue gradient hero | Stark white + one horizontal rule | No hero — tool opens directly to the search input |

# **2. Colour Palette**

Five colours total. One accent, one dark, one mid, one surface, one border. Nothing else.

| **Role** | **Hex** | **Used For** | **Do** | **Don't** |
| --- | --- | --- | --- | --- |
| **Ink** | **#0f172a** | Headings, labels | Page title, column headers | Body text, borders |
| **Slate** | **#475569** | Body text, descriptions | Paragraphs, table cell values | Headings, icons |
| **Accent** | **#1a56db** | CTAs, active states | Search button, active chip | Backgrounds, decorative use |
| **Surface** | **#F8FAFC** | Table row alt, inputs | Even table rows, search bar | Cards, panels |
| **Border** | **#CBD5E1** | Dividers, table lines | Table borders, input border | Text, backgrounds |

Rule: the accent colour (#1a56db) appears in exactly three places — the Search button, active filter chips, and column header backgrounds. Nowhere else.

# **3. Typography**

| UI Element / Type | Typography Specification |
| --- | --- |
| **Primary font** | DM Sans — clean, neutral, professional. Used for all UI text, labels, body. |
| **Data font** | DM Mono — monospaced. Used for phone numbers, pincode, API-derived values only. |
| **Why DM Sans** | Not Inter. Not Roboto. DM Sans has slightly wider letterforms that read well in dense tables. |
| **Why DM Mono** | Data fields like phone numbers and pincodes look intentional in mono — signals "this is real data". |
| **Load method** | Google Fonts — import in index.html, not in CSS. Faster parse. |

# **4. Layout & Spacing**

Single-page layout. No tabs, no sidebar, no modal popups. Everything lives on one scrollable page in three vertical zones.

### **Page Structure (top to bottom)**

| Attribute / Field | Description / Details |
| --- | --- |
| **Zone 1 — Header** | Tool name left-aligned. No nav, no logo, no hamburger. Just the name and a one-line description. |
| **Zone 2 — Search** | Two text inputs side by side + Search button. Full width. Clean horizontal rule below. |
| **Zone 3 — Filters** | Appears only after search. City chips row + Type chips row. Compact, no card/box around them. |
| **Zone 4 — Table** | Full-width results table. Result count + Download CSV button on the same line above it. |
| **Zone 5 — Footer** | One line. Tool name + version. No links, no social, no copyright block. |

### **Spacing Rules**

| Layout Component | Design Specification |
| --- | --- |
| **Page padding** | 48px left/right on desktop. No full-bleed sections. |
| **Section gap** | 32px between each zone. Not 24px, not 48px. |
| **Input height** | 40px. Same height for both inputs and the button. Aligned on one baseline. |
| **Table row height** | 44px. Enough breathing room without feeling spacious. |
| **Filter chip gap** | 8px between chips. 16px between City row and Type row. |
| **Border radius** | 6px on inputs, buttons, chips, badges. Not 4px, not 12px. Consistent. |

# **5. Component Specifications**

## **5.1  Search Bar**

| Layout Component | Design Specification |
| --- | --- |
| **Layout** | Two inputs + one button on a single row. Equal width inputs, fixed-width button (120px). |
| **Placeholder** | Location: "e.g. Jharkhand"  ·  Keyword: "e.g. institute" |
| **Input border** | 1px solid #CBD5E1. On focus: 1px solid #1a56db. No box-shadow on focus — just border change. |
| **Button** | Background #1a56db. Text white. No gradient. No shadow. Hover: opacity 0.88. |
| **Error state** | If empty on submit: border turns red (#DC2626), small text below input — "This field is required". |

## **5.2  Filter Chips**

| UI Element / Component | Visual & Interactive Spec |
| --- | --- |
| **Default state** | Border 1px solid #CBD5E1. Background white. Text #475569. |
| **Active state** | Background #EFF6FF. Border 1px solid #1a56db. Text #1a56db. Checkmark icon left of label. |
| **Multi-select** | Multiple chips can be active simultaneously. No radio behaviour. |
| **"All" chip** | Dashed border. Resets that filter row only. Not styled as accent when active. |
| **Auto-generated** | Chip labels come from real API data — never hardcoded in the component. |

## **5.3  Results Table**

| UI Element / Component | Visual & Interactive Spec |
| --- | --- |
| **Header row** | Background #1a56db. White text. 11px uppercase. Not sticky. |
| **Alternating rows** | Even rows: #F8FAFC. Odd rows: white. No hover highlight color change — just cursor change. |
| **Phone / PIN** | Rendered in DM Mono. Looks immediately different from name/address text — intentional. |
| **Rating** | Number + small star icon. Not a star-fill bar — just "4.2 ★". Keeps table clean. |
| **Type badge** | Pill shape. Each type gets a fixed colour: Coaching=blue, College=green, University=purple, School=amber. |
| **Long text** | Truncated with ellipsis. Full text visible on hover via browser title attribute. |
| **Empty state** | Centered text: "No results match your filters." + "Try removing a filter." Below that, nothing. |

## **5.4  Download CSV Button**

| UI Element / Component | Visual & Interactive Spec |
| --- | --- |
| **Position** | Top-right, same line as result count. Not a floating button, not at the bottom. |
| **Style** | Ghost button — border 1px solid #1a56db, text #1a56db, background transparent. |
| **Hover** | Background #EFF6FF. Border stays. No shadow. |
| **Label** | "Download CSV" with a small download icon left. No tooltip needed. |
| **Behaviour** | Downloads only currently filtered rows — not all results. |

# **6. What to Avoid  (The Anti-AI Checklist)**

Before shipping any screen, check every item below. If any of these appear in the final UI, fix them.

| **Anti-pattern** | **Why it looks AI-generated** | **Fix** |
| --- | --- | --- |
| Purple/blue gradient background | Most common AI template default | Plain white (#ffffff) background only |
| Glassmorphism cards | Overused AI aesthetic — frosted blur panels | No blur, no transparency, no backdrop-filter |
| Box shadows on everything | AI adds shadow-lg to every card and button | Zero box-shadow in the UI — borders only |
| Gradient text headings | Background-clip gradient text = instant AI tell | Flat colour headings only |
| Animated number counters | Count-up on load = AI portfolio template | Static numbers — no animation |
| Emoji in UI labels | AI loves adding 🔍 and 📊 to buttons | Icon library (Lucide) only — no emoji |
| Full-bleed coloured hero | Dark navy hero with white text = AI default | No hero section — start with the search bar |
| CSS class names like "wrapper__inner--card" | BEM generated by AI without context | Semantic names: .search-bar, .results-table |
| console.log left in production | AI always leaves debug logs | Remove all logs before deploy |
| aria-label="button" | AI forgets meaningful accessibility labels | aria-label="Search for businesses" |

# **7. Accessibility Rules**

| Accessibility Rule | Contrast Check Details |
| --- | --- |
| **Colour contrast** | All text must pass WCAG AA — minimum 4.5:1 ratio. Slate (#475569) on white = 5.9:1. Passes. |
| **Keyboard nav** | Tab order: Location input → Keyword input → Search button → Filter chips → Table rows. |
| **Focus ring** | Visible focus ring on all interactive elements. Use outline: 2px solid #1a56db — not outline:none. |
| **Screen reader** | Table has proper <thead>, <tbody>, <th scope="col">. Filter chips use role="checkbox" aria-checked. |
| **Loading state** | aria-live="polite" on results area — screen reader announces when results load. |
| **Error messages** | Input errors linked via aria-describedby — screen reader reads the error with the field. |
